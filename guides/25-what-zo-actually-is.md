Zo is not a chatbot that happens to know how to say things in a pleasant voice. That version is too small. It is a personal computer on your server, with files, a browser, integrations, automations, hosting, and AI all living in the same place. When it works, it feels less like asking a model a question and more like handing a task to a system that can actually touch the world. The important part is not the chat box. It is the wiring behind it.

> Zo is a computer with a brain, not a brain with a demo.

That difference matters because the work is different. A chatbot can answer. Zo can answer, then open a browser, read your inbox, write a file, run a service, publish a page, or wait until tomorrow morning and do the thing again. Same conversation. Different muscle.

## The useful model

Think of Zo as your own server with a layer of judgment on top.

The server side matters because your files are there. Your sites can live there. Your services can run there. Your automations can read from there. If you build something on Zo, it is not floating in somebody else's app drawer. It sits next to the rest of your work and can use the same files, the same folders, and the same AI.

The judgment layer matters because Zo does not just store and serve. It can decide which tool makes sense. If a task needs a browser session, it can use the browser. If it needs a connected app, it can use a plugin. If it needs a recurring schedule, it can become an automation. If it needs a different policy or voice, it can run under a persona.

That is why the platform can feel strange at first. It is not one product. It is a stack of products that talk to each other.

## What Zo includes

At a minimum, Zo gives you five things that belong together instead of living in separate tabs.

1. **Files.** Your workspace is real. Markdown, code, notes, databases, assets. The stuff you make lives there.
2. **A browser.** Zo can open real sites, sign in, and act as you on services that have no cleaner integration.
3. **Integrations.** Gmail, Calendar, Notion, GitHub, Stripe, and the long tail through the app catalog.
4. **Hosting.** Space, Sites, Services, and zo.pub for the things you want to put online or share.
5. **Automation.** Zo can run a prompt on a schedule, which turns a one-off task into a background habit.

Those pieces are the point. The chat window is just the front door.

## What this changes

If you treat Zo like a chatbot, you will ask it questions and forget it.

If you treat Zo like a computer, you start doing things that compound. You make a tiny page, connect one app, keep one folder in sync, set one automation, write one rule. Then the next time you come back, there is something there. A little structure. A little custody. A little leverage.

That is the real promise. Not that Zo talks well. That it helps you keep your work in one place and do more with it.

## The one sentence to keep

Zo is a computer that can act, not just answer.

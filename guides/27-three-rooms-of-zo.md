Zo feels simpler once you stop treating every part of it like a chat window. You actually work in three rooms: chat, workspace, and terminal. Each one is useful. Each one is bad at the others' job. The mistake is trying to make one room do all three.

> Chat is where you decide. Workspace is where you keep the thing. Terminal is where you make it move.

## Chat

Chat is for steering. It is where you say, "help me decide," or "write this so it sounds like a person who has actually used the thing."

Use it when you want Zo to think, explain, compare, draft, decide, or take a sequence of actions on your behalf. Chat is where you say what you want in plain English and let Zo pick the route. This is the room for questions like:

1. "What should I build first?"
2. "Rewrite this so it sounds less like a brochure."
3. "Find the bug in this flow."
4. "Make me a tiny site that does one thing."

Chat is also where you hand off context. You can tell Zo what matters, what to avoid, and what good looks like. That is the point. Steering, not storage.

## Workspace

The workspace is for files. If Zo writes a note, a draft, or a little database, this is where it should live. This is where the thing exists after chat stops talking about it. Markdown, code, notes, screenshots, assets, databases, docs. If you want to keep it, search it, or hand it to another session later, it belongs here. Use the workspace when you want something durable or inspectable. If Zo writes a draft, the draft should live in a file. If Zo makes a site, the site lives in a folder. If Zo captures a decision, it should end up in a document, not just in memory. The common beginner mistake is trying to use chat as a filing cabinet. That works until it does not. Then you spend ten minutes asking Zo to remember something you never saved.

## Terminal

The terminal is for commands. This is where exactness lives: `grep`, `git`, `curl`, scripts, logs, conversions, and the little emergencies you do not want to explain twice. Use it when you need exactness: `grep`, `git`, `curl`, scripts, installs, logs, conversions, file operations that are easier to do directly than by conversation. The terminal is where Zo gets sharp. It is also the room where things can get messy fastest, which is why it should be used on purpose. If you need a command, use the command. If you need a decision, stay in chat. If you need a file, write the file.

## The clean division

A better rule of thumb:

1. Use chat for decisions.
2. Use the workspace for files.
3. Use the terminal for commands.

That division sounds obvious until you watch people ignore it. Then the whole session turns into a long argument with the wrong room.

## The useful habit

When you finish a session, ask one question: where did the useful thing land?

If the answer is "nowhere," you probably talked about it too much.

If the answer is a file, a folder, or a command result you can reproduce, Zo did its job.
